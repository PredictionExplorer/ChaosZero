# V4 symbolic accounting checks

The suite executes the production `GameFundedOutcomeMarket`, its ERC-1155 accounting, immutable read helper and settlement vault. Each Halmos `check_` argument ranges over its entire Solidity type subject to the bounds below. The [Solidity harness](../../test/symbolic/GameFundedSymbolic.t.sol) calls public contract entry points and inspects balances and ledgers after the transitions.

| Property                                                            | Symbolic inputs and assertions                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Only authenticated grants fund a cycle                              | Up to `2^96 − 1` unsolicited base units and an 8,000 CST record for another market leave cycle 1 unfunded. The correct grant followed by repeated public synchronization places exactly 1,000 CST into each of the eight pools.                                                                                                                                                                       |
| Stale or unbacked records cannot be replayed under another cycle ID | An unchanged cumulative ledger and then an increased but unbacked record both produce the expected funding error. An arbitrary `uint64` dust transfer leaves the cursor, funded flag and existing collateral intact.                                                                                                                                                                                  |
| Each initial funding path consumes a grant once                     | A symbolic selector takes all three reachable opening paths: explicit sync, a funded buy or a complete-set split. Further sync, split and trade calls keep the cursor fixed. Exact balances distinguish the 8,000 CST grant from the trader’s input.                                                                                                                                                  |
| Quiet cycles are credited exactly once                              | With 0–255 unused intervening cycles and an arbitrary `uint64` transfer, the next sync credits the entire cumulative delta once. A replay preserves the credited balance and the unrelated CST remains outside the eight pools.                                                                                                                                                                       |
| Capacity defers only excess funding                                 | At the first cumulative grant above opening capacity, plus 0–255 additional grants, the cursor records total issuance, pool custody is capped, and pending carry accounts for every remaining base unit after replay.                                                                                                                                                                                 |
| All 256 outcomes reserve the correct winning supplies               | Each question holds a distinct amount of paired YES/NO units plus directional YES positions. After the next cycle opens, every question’s vault entry equals its own winning supply for every possible final answer mask. Only unowed CST enters the next cycle.                                                                                                                                      |
| Older claims outlive two rollovers                                  | Across three active cycles, two independent `uint64` values size the old paired position and the portion merged. A symbolic YES/NO result selects the directional holder’s entitlement. A separate `uint64` gift to the vault stays outside liabilities. Late merging and both holders’ claims pay exactly their remaining units, leave the second cycle backed, and preserve the third cycle’s pool. |

## Boundaries

The external game fixture records cycle-specific grants and credits the matching CST to the market. For a gap it aggregates the unconsumed grants with the same cumulative amount and custody that repeated real game transfers would leave. The exact-transfer token models balances and approvals. The outcome fixture reports the current cycle open and returns its chosen immutable eight-bit answer once it closes. One negative property deliberately supplies stale and unbacked records to check the market’s rejection. Separate game integration and archive-fork suites cover the upgrade, deployed CST, and actual outcome computation.

The proofs cover the specified transaction sequences, two non-contract holders, and ordinary, concrete AMM trade sizes. They do not establish an invariant for arbitrary unbounded trade histories, receiver callbacks, or future upstream upgrades. The [concrete multi-holder test](../../test/GameFundedClaimBacking.t.sol) exercises five real local-game cycle grants and delayed claims from two earlier cycles. The [stateful Foundry suite](../../test/GameFundedMarketInvariant.t.sol) explores additional action sequences.

## Run locally

Use Foundry 1.7.1, Python 3.13, and the repository’s pinned submodules. From the repository root:

```sh
python3.13 -m venv .local/symbolic/venv
. .local/symbolic/venv/bin/activate
python -m pip install --require-hashes --no-deps -r verification/symbolic/requirements.txt
python -m unittest discover -s verification/symbolic
python verification/symbolic/verify.py
```

CI installs hash-locked wheels for Linux. Where a platform needs to build the Keccak extension, a working C compiler and system SDK are required. The requirements lock records its exact regeneration command. It pins Halmos 0.3.3 and Z3 4.12.6.0.

The runner checks the production Solidity settings (0.8.35, via IR, one million optimizer runs, Osaka) and uses a fresh temporary Forge cache and output directory for each execution. It validates its own machine-readable report before atomically publishing it at `.local/symbolic/results.json`. A failed run with a report writes a separate `results-failed-*.json` file. Every complete scenario is wrapped in an asserted external call, so an unexpected revert cannot silently prune a failing execution. The report checker requires every named property, expected normal-return coverage (including all 256 masks), zero counterexamples, zero blocked paths, and zero loops cut short at the unroll bound. A missing or incomplete report, solver timeout, or nonzero tool exit fails the workflow.
