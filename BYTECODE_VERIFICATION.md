# V4 bytecode verification

Run `pnpm verify:bytecode` after installing the repository’s pinned tools and submodules. CI runs the same check from source on pull requests to V4. Verification does not need a signing key, explorer account, or blockchain transaction.

| Target                          | Compiler identity and evidence                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Archived single-question market | Rebuilds the two original source units using solc 0.8.35, Osaka, IR, one million optimization runs and the original forge-std remapping in a temporary directory. Compares every creation byte and the game constructor argument against the checked-in broadcast record. Checks the actual game and CST immutable words and full runtime hash.                                                                                                              |
| Original eight-question market  | Rebuilds the production Hardhat adapter and market, their original constructor arguments (including the round-two baseline), and the vault and helper emitted by the market’s constructor. The vault is read from the **parent market's** compiler job: the separate vault compilation has different metadata. Checks both CREATE addresses and both deterministic child addresses, full runtime hashes and the frontend’s original market/adapter bindings. |
| V4 successor                    | Pins the Foundry unsigned creation input with real Arbitrum CST, game and existing adapter arguments, and the market, vault and helper runtime **templates**. These appear as build fingerprints only: the witness does not assign a production address or claim a deployment.                                                                                                                                                                               |

[Public witnesses](deployment/arbitrum-bytecode.json) record the historical transaction hashes, receipt blocks, block hashes and exact runtime fingerprints. See the [legacy creation](https://arbiscan.io/tx/0x77aba10c8de31c9359dc8395291390d4724119e1a939c4aee14672396e013196), [adapter creation](https://arbiscan.io/tx/0x409542c28b2f78348bed33fe7f128769e7c050af43e4de0fba48a265bd21a4a1), and [eight-question market creation](https://arbiscan.io/tx/0x9360e041dc6ff3761f5e8cf96166fec94b533f8c996f71362ded670d8ee48b92). The offline gate reproduces these witnesses, not chain consensus. With an archive endpoint configured as `ARBITRUM_RPC_URL`, run `pnpm verify:bytecode --rpc` to confirm each mined transaction, its canonical receipt block, and all five deployed runtimes against Arbitrum One. Each group of runtime reads is bracketed by uncached canonical block-hash checks. On failure, the CLI prints a fixed stage label without reflecting RPC diagnostics or endpoint credentials.

For the successor, `pnpm prepare:game-funded` emits unsigned calldata. A separately authorized deployment can later be inspected using `pnpm prepare:game-funded <creation-tx-hash>`. Inspection checks the creation calldata, successful receipt, chain, sender-derived CREATE address, vault/helper CREATE nonces, all three deployed runtimes, reported bindings, 8,000 CST grant amount, and block canonicality. Every byte including metadata is compared. Only compiler-identified immutable slots are filled from expected values. External library links, unresolved bindings, and invalid offsets are rejected. The local browser smoke exercises this same inspector on a disposable chain.

Intentional changes to production code or build settings require re-review of the V4 fingerprints in the same change. Historical fingerprints belong to their original deployments.
